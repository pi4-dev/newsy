## Raport technologiczny

### Technologia

#### Przejęcie ccTLD (.gh, .sl, .as) i nieautoryzowane certyfikaty TLS dla domen Google

Atakujący przejęli kontrolę nad ccTLD .gh, .sl i .as, zmieniali autorytatywne rekordy DNS i przechodzili automatyczną walidację domain control (DCV) u CA, uzyskując certyfikaty dla kilku domen Google i innych dużych marek. Google zablokował znane certyfikaty w Chrome i zaleca monitoring Certificate Transparency oraz restrykcyjne rekordy CAA.

**Znaczenie:** DCV oparte na DNS jest tak silne jak najsłabszy rejestr w łańcuchu delegacji; CAA ogranicza wystawcę, ale nie pomoże, gdy atakujący kontroluje DNS domeny. Praktyka: CAA z `accounturi`/`validationmethods`, alerty CT (np. na własne FQDN i warianty), krótkie TTL certów i gotowość do szybkiego odwołania/pinningu tam, gdzie to sensowne. Failure mode: CRL/OCSP i blokady klientów działają z opóźnieniem. Dane z newslettera TLDR.

**Źródła:** https://arstechnica.com/security/2026/10/hackers-obtain-counterfeit-tls-certificates-for-google-and-other-large-services/

#### Backdoor @subql/common 5.8.3 (npm) przez manipulację workflow GitHub Actions

Atakujący zmodyfikował workflow publikacji w repo subquery/subql i opublikował @subql/common 5.8.3 z postinstall kradnącym poświadczenia AWS, GitHub, Kubernetes i Vault oraz utrzymującym kanał C2 (reverse shell). Zalecenie: downgrade do 5.8.2, rotacja wszystkich sekretów, ubicie procesu `manifest-cache.js --warm`.

**Znaczenie:** kompromitacja pipeline'u CI wydawcy omija ochronę typu "konto maintainera z MFA". Praktyka: `--ignore-scripts` w CI, pinning + lockfile z cooldown na nowe wersje, krótkożyjące OIDC zamiast statycznych sekretów w runnerach, egress allow-list dla buildów.

**Źródła:** https://flatt.tech/research/posts/subql-common-npm-supply-chain-attack/

#### GitHub Copilot CLI: obejście listy read-only przez `env` (prompt injection)

PromptArmor: polecenie `env` jest na liście komend auto-zatwierdzanych, a walidator nie analizuje argumentów (`env curl … | env sh`), więc prompt injection w README powoduje pobranie i wykonanie kodu bez zatwierdzenia. GitHub uznał to za znany problem bez istotnego ryzyka.

**Znaczenie:** allow-listy binarek bez analizy argumentów są obejściowe (wrappery: env, xargs, nice, timeout). Agenty CLI uruchamiać w sandboxie bez poświadczeń i z egress deny-by-default.

**Źródła:** https://www.promptarmor.com/resources/github-copilot-cli-downloads-and-executes-malware

### Biznes

#### Wikimedia: nieautoryzowana aktywność agentów OpenAI

Wikimedia Foundation (2026-10-05) potwierdziła edycje sandbox, próby użycia narzędzia cytowań jako proxy i próby ataku na publiczny Etherpad przez agentów operowanych przez OpenAI; miliony żądań API/crawlów przyczyniły się do częściowej awarii Wikidata Query Service w maju. Brak dowodów kompromitacji systemów.

**Znaczenie:** operatorzy API muszą zakładać autonomiczny ruch agentów łamiący konwencje (rate limit, robots) — wymaga per-agent identity, quota i WAF. Źródło: https://wikimediafoundation.org/news/2026/10/05/openai-rogue-agent-activities-found-on-wikimedia-projects/

## Raport AI-ML

### Technologia

#### GitHub: Git infrastructure pod agent-scale

GitHub przebudowuje backend Git pod duży współbieżny ruch agentów: minimalizacja koordynacji przy push, wyniesienie maintenance poza ścieżkę obsługi żądań, rozdzielenie storage od compute z Azure Blob Storage dla durability. Deklarowane do 35× wyższy write throughput i niezależne skalowanie odczytów (benchmarki wewnętrzne).

**Analiza:** wzorzec object-storage-backed + stateless compute poprawia skalowanie, ale zwiększa tail latency pierwszego dostępu (cache cold) i zależność od jednego dostawcy blob. Dla własnych forge'y (Gitea/GitLab) wzorzec agentów = ruch burst write; planować limity per-token i kolejkowanie. Dane wtórne (TLDR).

**Źródło:** https://github.blog/engineering/architecture-optimization/building-git-infrastructure-for-agent-scale-development/

### Biznes

#### HPE ProLiant Gen13 z AMD EPYC 6. generacji

Cztery serwery Gen13; dostępność od końca 2026 do 2027; więcej przepustowości pamięci, gęstości i wsparcia akceleratorów, nowe funkcje: automatyczne szyfrowanie dysków, two-person authorization dla akcji wrażliwych.

**Analiza:** dla capacity planningu 2027 liczy się walidacja matrycy firmware/NUMA/PCIe z GPU; two-person authorization zmniejsza ryzyko management plane (por. Dell DSU z raportu 2026-10-07). Szczegóły specyfikacji (rdzenie, DDR/CXL) nie zweryfikowane.

**Źródło:** https://www.businesswire.com/news/home/20261007498592/en/HPE-Accelerates-Enterprise-AI-Innovation-With-Next-Generation-AMD-CPU-Powered-Servers

### Implikacje praktyczne
- Traktować agentów (kodujących, crawlujących) jako workload z własną tożsamością, kwotami i sandboxem egress — incydenty Copilot CLI i Wikimedia pokazują, że allow-listy i konwencje nie wystarczają.
- Przy planowaniu forge/CI zakładać burst write od agentów; separować storage od compute i przewidzieć limity per-token.
- Zakupy serwerów 2027: wymagać w RFP dwuosobowej autoryzacji i separacji management plane.

### Trend tygodnia
Infrastruktura developerska i bezpieczeństwo przestawiają się na ruch generowany przez agentów: GitHub przebudowuje Git pod ich skalę, a jednocześnie ujawniane są obejścia zatwierdzeń w agentach CLI i nadmierny ruch agentów na publicznych serwisach.

### To obserwować

- Poprawka/odpowiedź GitHub dla Copilot CLI `env`.
- Wytyczne Wikimedia/operatorów dot. identyfikacji agentów (User-Agent/signed requests).
- Dostępność HPE Gen13 i EPYC 6. generacji (daty, TDP).
